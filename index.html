1Introdução a grafos

Por que grafos?

Exemplo das aulas — chuvas no Rio Grande do Sul (2024) e deslizamentos no litoral de São Paulo (2023). Perguntas que queremos responder com um computador:

  • Alguma área ficou isolada? → componentes conexas
  • Como sair de casa até um destino? → caminhos / caminho mínimo
  • Qual o mínimo de intervenções para restaurar todos os pontos isolados? → conectar componentes

Outros usos citados: dependências entre partes de uma produção, traçar caminhos num mapa, conectar cidades com o mínimo de ligações, criar agrupamentos ou equipes.

Definição formal

Definição — Grafo

Um grafo é uma tupla G = (V, E) com dois conjuntos:

  • V = {0 … N−1} — os vértices, numerados de 0 até N = |V|;
  • E = {(v, w) | v, w ∈ V; v ≠ w} — as arestas (edges): pares de vértices. Toda aresta é direcionada: tem um início v e um destino w.

Se o grafo tem pesos, há ainda uma função w : E → ℝ que dá um número real a cada aresta.

Nesta disciplina não há loops (v ≠ w) nem mais de uma aresta por par de vértices. (Alguns handouts numeram de 1 a N; nos exercícios de modelagem e em C usamos 0 a N−1.)

Tipos de grafos

Sem pesosCom pesos
Direcionadoassociação pode ou não ser bidirecional; aresta com setacada aresta tem um número real (custo, distância, tempo…)
Não direcionadopara toda aresta (v,w) existe também (w,v); desenhada sem setasas duas direções têm o mesmo peso
Atenção — contagem de arestas

Pela definição formal, um grafo não direcionado contém as duas direções: cada linha desenhada corresponde a 2 pares em E (e a matriz tem 2 uns por linha desenhada). Se a questão pedir "número de arestas" de um grafo não direcionado, explicite se está contando linhas desenhadas ou pares em E.

Graus

  • Grau de entrada de um vértice: número de arestas que chegam nele.
  • Grau de saída: número de arestas que saem dele.
  • Em grafos não direcionados falamos só em grau — entrada e saída são iguais.

Conferência: soma dos graus de entrada = soma dos graus de saída = |E| = 6. Vértice 0: menor grau de entrada (0) e maior grau de saída (2). Os vértices 1 e 3 têm o maior grau de entrada (2).

Matriz de adjacências

É a representação usada na disciplina: uma matriz quadrada A ∈ ℝN×N.

Sem pesos

A[i][j] = 1 se (i, j) ∈ E; 0 caso contrário

Com pesos

A[i][j] = w(i, j) se (i, j) ∈ E; ∞ caso contrário

Perguntas de reflexão do slide — respostas
  • Quantas arestas chegam em j? Soma da coluna j (grau de entrada).
  • Quantas arestas saem de i? Soma da linha i (grau de saída).
  • Grafo não direcionado? A matriz é simétrica: A[i][j] = A[j][i]; grau = soma da linha = soma da coluna.
  • Com pesos? A posição guarda o peso; ausência de aresta vira ∞ (não 0, pois 0 pode ser um peso válido e, nos algoritmos de menor caminho, ∞ nunca "ganha" de um caminho real).

Modelagem: 4 perguntas para transformar um problema em grafo

  1. O que cada vértice representa?
  2. Que relação entre vértices uma aresta representa?
  3. Essa relação tem direção ou é sempre simétrica?
  4. Essa relação tem pesos/preferências ou todas as arestas são equivalentes?

Exemplo do handout: influência em redes sociais

Log: usuários, posts de cada usuário e quem curtiu cada post. Queremos saber: (1) quais usuários postaram algo curtido; (2) qual usuário tem mais curtidas recebidas; (3) qual usuário mais curtiu posts.

  • Vértices: usuários. Aresta u → v: "u curtiu algum post de v". Direcionado: sim (curtir não é recíproco). Pesos: não são necessários (opcionalmente, o nº de curtidas).
  1. Quem postou algo curtido? Colunas com pelo menos um 1 (grau de entrada > 0). Aqui: 1, 2, 3 e 5 (o 4 nunca foi curtido).
  2. Maior número de curtidas recebidas? Coluna de maior soma (maior grau de entrada): usuário 5 (curtido por 1, 2 e 3).
  3. Quem mais curtiu? Linha de maior soma (maior grau de saída): empate entre 2 e 3 (3 cada).

2Representação computacional (em C)

Formal → computacional. V pode ser representado só pelos números: guardamos |V| = Nv. E vira a matriz A (Nv × Nv) definida na seção anterior.

Array de arrays: double **

Cada linha é um array (double *); a matriz é um array cujos elementos são essas linhas (double **). O acesso é natural: mat[2][5] = 5; (linha 2, coluna 5).

Alocação, inicialização e liberação

  1. Nível 1 — array com as V linhas: double **mat = malloc(4 * sizeof(double *));
  2. Nível 2 — V alocações, uma por linha: for (int i = 0; i < 4; i++) mat[i] = malloc(4 * sizeof(double));
  3. Inicializar — o malloc não inicializa: sem pesos → 0; com pesos → INFINITY (#include <math.h>; double infinity = INFINITY;).
  4. Liberar — também em dois níveis: primeiro cada linha, depois o array de ponteiros.
#include <stdio.h>
#include <stdlib.h>
#include <math.h>

/* V vértices; ponderado = 0 (matriz de 0/1) ou 1 (pesos, sem aresta = INFINITY) */
double **cria_matriz(int V, int ponderado) {
    double **mat = malloc(V * sizeof(double *));      /* nível 1: V ponteiros */
    for (int i = 0; i < V; i++) {
        mat[i] = malloc(V * sizeof(double));          /* nível 2: uma linha */
        for (int j = 0; j < V; j++)
            mat[i][j] = ponderado ? INFINITY : 0;
    }
    return mat;
}

void libera_matriz(double **mat, int V) {
    for (int i = 0; i < V; i++) free(mat[i]);         /* primeiro as linhas */
    free(mat);                                        /* depois o array de ponteiros */
}
Para lembrar
  • Matriz de V vértices = V + 1 chamadas a malloc e V + 1 a free.
  • Memória: O(V²) independentemente do número de arestas. Testar se (i,j) ∈ E é O(1) (EH_VIZINHO); listar os vizinhos de um vértice é O(V) (percorrer a linha).
  • Sub-rotinas supostas nos handouts: NVERTICES(G) e EH_VIZINHO(G, i, j).

3Caminhos, componentes conexas e DFS

Caminho

Definição — Caminho

Um caminho de tamanho k em G = (V, E) é uma sequência de vértices v0, v1, …, vk tal que cada aresta (vi, vi+1) está em E. Ele começa em v0 e termina em vk. (Em grafos sem pesos, tamanho = nº de arestas.)

Componente conexo

Definição — Componente conexo (grafo não direcionado, sem pesos)

Seja G = (V, A). Um subconjunto C ⊆ V é um componente conexo se e somente se:

  1. para todo par v, w ∈ C existe um caminho que começa em v e termina em w;
  2. para todo v ∈ C e w ∈ V − C, não existe caminho entre v e w.

Interpretação: componentes são grupos de vértices isolados uns dos outros — há caminho entre vértices do mesmo componente e nenhum entre componentes diferentes. "Existem regiões isoladas?" ⇔ "O grafo tem mais de um componente conexo?" (vértices = cidades, arestas = estradas).

Mínimo e máximo

Todo grafo com |V| > 0 tem no mínimo 1 (grafo todo conectado) e no máximo |V| componentes (nenhuma aresta: cada vértice sozinho).

Caminho que sai de C?

Não é possível. Se um caminho entre dois vértices de C passasse por um vértice fora de C, esse vértice seria alcançável a partir de C, contrariando a condição 2.

Busca em profundidade (DFS)

  • Algoritmo recursivo e curto que visita todos os vértices acessíveis a partir da raiz.
  • Precisa ser chamado mais de uma vez para cobrir o grafo todo se ele tiver vários componentes.
  • Serve para: contar/identificar componentes, encontrar ciclos, ordenação topológica.
DFS(G, v, visitado)
    visitado[v] <- VERDADEIRO
    PARA CADA VIZINHO w DE v FAÇA
        SE NÃO visitado[w] ENTÃO
            DFS(G, w, visitado)

Nos exercícios, "a ordem de visitação dos vizinhos é alfabética" (ou crescente). Numere os vértices na ordem em que são visitados pela 1ª vez (pré-ordem).

Simulação: DFS a partir de D (vizinhos em ordem alfabética)

Ordem visitada: D → B → A → C. Os vértices F, G, I, J ficam sem número: D não os alcança — eles são outro componente.

Em A, o vizinho C ainda não foi visitado e vamos a ele; em C, o vizinho D já foi visitado e não é o predecessor (A) ⇒ achamos um ciclo (D-B-A-C).

Propriedades a saber de cor
  1. Se há um só componente, uma DFS visita todos os nós.
  2. Quando há ciclo, em algum momento encontramos um vizinho já visitado que não é o predecessor.
  3. Se a DFS inicia num componente, os vértices dos outros componentes ficam sem número ⇒ precisamos de uma DFS por componente.

Algoritmo IDENTIFICA-COMPONENTES(G, LABELS)

Saída: um array LABELS em que cada vértice recebe o identificador (a partir de 1) do seu componente; dois vértices estão no mesmo componente ⇔ mesmo rótulo. Para o grafo acima: [1, 1, 1, 1, 2, 2, 2, 2] (se começamos por A, B, C ou D) ou [2, 2, 2, 2, 1, 1, 1, 1] (se começamos por F, G, I ou J) — ambas corretas.

Dicas do handout: (1) LABELS chega não inicializado — inicialize com um valor que não seja rótulo válido (ex.: 0 ou −1) para distinguir "não visitado" de "já rotulado"; (2) pode ser preciso criar mais de uma função; (3) o máximo de componentes é |V|.

IDENTIFICA-COMPONENTES(G, LABELS)
    N <- NVERTICES(G)
    PARA v <- 0 ATÉ N-1 FAÇA LABELS[v] <- 0        # 0 = ainda sem rótulo
    c <- 0
    PARA v <- 0 ATÉ N-1 FAÇA
        SE LABELS[v] = 0 ENTÃO                     # v ainda não foi alcançado por nenhuma DFS
            c <- c + 1                             # novo componente
            ROTULA(G, v, c, LABELS)               # DFS marcando todo o componente
    DEVOLVA c

ROTULA(G, v, c, LABELS)                           # é uma DFS: LABELS faz o papel de "visitado"
    LABELS[v] <- c
    PARA w <- 0 ATÉ NVERTICES(G)-1 FAÇA
        SE EH_VIZINHO(G, v, w) E LABELS[w] = 0 ENTÃO
            ROTULA(G, w, c, LABELS)
void rotula(double **A, int V, int v, int c, int *labels) {
    labels[v] = c;
    for (int w = 0; w < V; w++)
        if (A[v][w] != 0 && labels[w] == 0)
            rotula(A, V, w, c, labels);
}

/* devolve o número de componentes; labels[v] em 1..c */
int identifica_componentes(double **A, int V, int *labels) {
    for (int v = 0; v < V; v++) labels[v] = 0;
    int c = 0;
    for (int v = 0; v < V; v++)
        if (labels[v] == 0) { c++; rotula(A, V, v, c, labels); }
    return c;
}

complemento Com matriz de adjacências, cada vértice varre sua linha (O(V)) e é rotulado uma única vez ⇒ O(V²) no total (com listas de adjacência seria O(V + E)).

Problemas relacionados: segmentação de imagens (grafos de pixels), dependências em projetos, agrupamentos (clustering).

4Caminhos mínimos em grafos sem pesos (BFS)

Problema: dados vértices s e t, encontrar o caminho de menor tamanho entre eles (ex.: navegação). Sem pesos: tamanho do caminho = número de arestas.

Ideias centrais (think-pair-share)

1 · Existe um só caminho mínimo?

Não. Podem existir vários caminhos do mesmo tamanho mínimo. Contra-exemplo: num ciclo de 4 vértices A-B-D e A-C-D, ambos A→B→D e A→C→D têm tamanho 2.

2 · A DFS encontra o menor caminho?

Não. A DFS acha um caminho, que pode ser longo. No grafo abaixo, de A a G, a DFS (vizinhos em ordem alfabética) segue A→B→C→D→E→G (5 arestas), mas o mínimo é A→F→G (2 arestas).

3 · "Existe caminho de s a t com no máximo k arestas?"
  • Se SIM — convenço mostrando o próprio caminho (um certificado que se verifica em O(k)).
  • Se NÃO — convenço mostrando que o conjunto de vértices alcançáveis com até k arestas (calculado camada a camada) não contém t.

Busca em largura (BFS)

  1. Itera I = 1 … |V|;
  2. a cada iteração encontra todos os vértices a distância até I da raiz (expande "por camadas");
  3. se chegou no destino, para.

Implementação com uma fila (estrutura de dados queue_t, entrega da aula): vértices mais próximos da raiz saem primeiro (FIFO). O vetor pred reconstrói o caminho.

BFS(G, s, t)
    dist[v] <- -1 e pred[v] <- -1 PARA TODO v      # -1 = não alcançado
    dist[s] <- 0;  pred[s] <- s
    ENFILEIRA(fila, s)
    ENQUANTO fila NÃO VAZIA E dist[t] = -1 FAÇA
        u <- DESENFILEIRA(fila)
        PARA CADA VIZINHO v DE u FAÇA
            SE dist[v] = -1 ENTÃO                  # primeira vez que vemos v
                dist[v] <- dist[u] + 1
                pred[v] <- u
                ENFILEIRA(fila, v)
    PREENCHA path USANDO pred
    DEVOLVA path, dist[t]

Simulação: BFS de A até G

A fila sempre guarda vértices em ordem não decrescente de distância; por isso a primeira vez que alcançamos um vértice já é pelo caminho mais curto. Para A→G: dist[G] = 2, caminho A, F, G.

A fila circular

Como cada vértice entra na fila no máximo uma vez, um vetor de capacidade |V| basta. Para não "andar" pelo vetor, usamos índices módulo a capacidade:

  • ini = posição do próximo a sair; tam = quantos elementos há; cap = capacidade.
  • enfileira(x): dados[(ini + tam) % cap] = x; tam++;
  • desenfileira(): x = dados[ini]; ini = (ini + 1) % cap; tam--;
  • Vazia ⇔ tam == 0; cheia ⇔ tam == cap. Ambas as operações são O(1).
/* BFS em matriz de 0/1. Devolve o nº de arestas do caminho mínimo (-1 se não há). */
int bfs(double **A, int V, int s, int t, int *pred, int *dist) {
    int *fila = malloc(V * sizeof(int));          /* fila circular de capacidade V */
    int ini = 0, tam = 0;
    for (int i = 0; i < V; i++) { dist[i] = -1; pred[i] = -1; }
    dist[s] = 0; pred[s] = s;
    fila[(ini + tam) % V] = s; tam++;             /* enfileira s */
    while (tam > 0 && dist[t] == -1) {
        int u = fila[ini]; ini = (ini + 1) % V; tam--;   /* desenfileira */
        for (int v = 0; v < V; v++)
            if (A[u][v] != 0 && dist[v] == -1) {
                dist[v] = dist[u] + 1; pred[v] = u;
                fila[(ini + tam) % V] = v; tam++;        /* enfileira v */
            }
    }
    free(fila);
    return dist[t];
}

/* Reconstrói o caminho s..t a partir de pred; devolve o nº de vértices (0 se não há). */
int monta_caminho(int *pred, int s, int t, int *path) {
    if (pred[t] == -1) return 0;
    int n = 0;
    for (int v = t; v != s; v = pred[v]) path[n++] = v;
    path[n++] = s;
    for (int i = 0; i < n / 2; i++) { int x = path[i]; path[i] = path[n-1-i]; path[n-1-i] = x; }
    return n;
}
Cuidado

BFS minimiza o número de arestas, não a soma dos pesos. Em grafos com pesos ela pode devolver o caminho errado (próxima seção). complemento Custo com matriz: O(V²) (O(V + E) com listas de adjacência).

5Caminhos mínimos com pesos: Dijkstra e min-heap

Agora o "tamanho" de um caminho é a soma dos pesos das arestas. Perguntas do slide e suas respostas:

Por que BFS (e variações ingênuas) não servem?

A BFS funciona com pesos? Não.

De A a D, a BFS acha A→D (1 aresta, custo 10), mas A→B→C→D custa 6.

"Pegar as menores arestas primeiro"? Não.

De A a D, a menor aresta (1) leva a B e depois a D por 10: custo 11. O ótimo é A→C→D: 5. Olhar só a aresta ignora o que já foi gasto até chegar ali.

"Pegar os vértices mais próximos (da fonte) primeiro"? Sim!

Essa é a ideia do algoritmo de Dijkstra: o critério é a distância acumulada desde a fonte, não o peso da aresta isolada.

Algoritmo de Dijkstra

  • Menor caminho em grafos com pesos não negativos.
  • Ideia central: iterativamente pegar o vértice mais próximo da fonte.
  • Ao processar um vértice, a distância até ele não muda mais.

Entradas: G = (V, E) direcionado com pesos não negativos numa matriz quadrada P; s, t ∈ V (fonte e destino). Saída: array path com o caminho de s até t (ou vazio ∅ se não há) e o tamanho (custo) do caminho.

Estruturas auxiliares:

  • dist — distância (mínima conhecida) da fonte até cada vértice; inicia em ∞.
  • pred — predecessor de cada vértice no melhor caminho; inicia em −1.
  • h — conjunto de vértices já alcançados mas ainda não processados (essencial para um algoritmo rápido).

Simulação do handout (4 passos): (1) selecione o vértice não visitado K de menor distância à fonte; (2) para cada vizinho de K, atualize a distância se passar por K for melhor (relaxamento); (3) marque K como visitado; (4) continue até não haver vértices não visitados ou até chegar ao destino.

dist[s] <- 0
pred[s] <- s
INSERE s EM h

PARA i=1 até |V| FAÇA
    k <- elemento em h com menor dist

    PARA CADA VIZINHO j DE k FAÇA
        distK <- dist[k] + P[k, j]
        SE distK < dist[j] ENTÃO
            dist[j] <- distK
            pred[j] <- k
            INSERE j EM h        # não faz nada se já estiver em h
        FIM
    FIM
FIM

PREENCHA path USANDO O ARRAY pred
DEVOLVA path, dist[t]

(O elemento k sai de h ao ser processado. Se h esvaziar antes, o resto do grafo é inalcançável e dist[t] = ∞ ⇒ não há caminho.)

Simulação: fonte D, destino A

Passo a passo:

  1. h = {D}: processa D → C=3, F=4, E=2.
  2. menor é E (2): A = 2+5 = 7 (alcançado).
  3. depois C (3): A via C = 3+3 = 6 < 7 → atualiza.
  4. depois F (4): A via F = 4+1 = 5 < 6 → atualiza, pred[A] = F.
  5. processa A (menor de h) — destino alcançado, para.

Reconstrução: pred[A] = F, pred[F] = D, pred[D] = D (a fonte) ⇒ caminho D, F, A; custo dist[A] = 5.

Pegadinha

Os três caminhos de D até A (via C, E ou F) têm 2 arestas, mas custos 6, 7 e 5. Quem decide é o custo acumulado, não o número de arestas — por isso a BFS não resolve este problema.

Complexidade com vetor

  • Achar "o elemento de h com menor dist" guardando h num vetor: O(V); faço isso no máximo V vezes ⇒ O(V²).
  • distK é calculado no máximo E vezes (cada aresta é relaxada uma vez) ⇒ O(E).
  • Total: O(E + V²) = O(V²) (pois E ≤ V²).
/* Dijkstra com matriz P de pesos (sem aresta = INFINITY), versão O(V^2).
   Devolve dist[t] (INFINITY se não há caminho); preenche pred e dist. */
double dijkstra(double **P, int V, int s, int t, int *pred, double *dist) {
    int *done = calloc(V, sizeof(int));           /* 1 = já processado */
    for (int i = 0; i < V; i++) { dist[i] = INFINITY; pred[i] = -1; }
    dist[s] = 0; pred[s] = s;
    for (int it = 0; it < V; it++) {
        int k = -1;                               /* k = menor dist em h = alcançado e não processado */
        for (int v = 0; v < V; v++)
            if (!done[v] && dist[v] < INFINITY && (k == -1 || dist[v] < dist[k])) k = v;
        if (k == -1) break;                       /* h vazio: o resto é inalcançável */
        done[k] = 1;
        if (k == t) break;                        /* destino processado: dist[t] é definitiva */
        for (int j = 0; j < V; j++)
            if (P[k][j] != INFINITY) {            /* j é vizinho de k */
                double distK = dist[k] + P[k][j];
                if (distK < dist[j]) { dist[j] = distK; pred[j] = k; }
            }
    }
    free(done);
    return dist[t];
}

Pesos negativos: o Dijkstra quebra

O handout mostra o que acontece se houver pesos negativos (nas definições da disciplina todo peso é ≥ 0). A premissa "ao processar um vértice sua distância não muda mais" deixa de valer.

Fonte A, destino B. Dijkstra processa C (1) e depois B com dist[B] = 2 e para (destino processado). Mas A→D→B custa 100 + (−150) = −50 < 2: a resposta está errada.

Ciclo negativo A→D→F→A: 10 − 6 − 6 = −2. Cada volta no ciclo diminui o custo, então não existe menor caminho até B (tenderia a −∞). Dijkstra perde qualquer garantia: as distâncias dos vértices do ciclo continuam diminuindo, e a implementação pode devolver um valor errado ou nunca terminar.

Regra

Dijkstra só é correto com pesos não negativos. Com pesos negativos é preciso outro algoritmo (fora do escopo desta matéria).

Min-heap

Para pegar "o de menor dist" mais rápido que O(V), usamos um min-heap.

Propriedades do min-heap
  1. todo nó tem no máximo dois filhos;
  2. é "completo" à esquerda (todos os níveis cheios, exceto possivelmente o último, preenchido da esquerda para a direita);
  3. o valor de um nó é menor que (≤) o de seus filhos ⇒ o menor valor está na raiz.

Operações: INSERE(H, V) e MENOR(H) (devolve o menor valor e o remove). O max-heap é a versão alternativa: cada nó é maior que os filhos (raiz = máximo).

Representação como array (índices a partir de 0)

Nó no índice i → filhos em 2i + 1 e 2i + 2; pai em (i − 1) // 2 (divisão inteira). O heap é guardado por níveis, da esquerda para a direita.

INSERE
  1. colocar no final do heap;
  2. trocar com o pai se for menor;
  3. repetir o passo 2 até não dar mais (sobe até a raiz, no pior caso).
MENOR / REMOVE
  1. trocar o elemento 0 (raiz) com o último elemento;
  2. diminuir o tamanho do heap (o antigo menor sai);
  3. trocar a raiz com o menor dos filhos até não dar mais (desce).
Complexidade

A altura do heap é ⌊log₂ N⌋ ⇒ INSERE e MENOR custam O(log N). Ver o menor sem remover é O(1).

Dijkstra melhorado com min-heap

No heap guardamos pares (dist, vértice), usando dist como valor de comparação. Em vez de "atualizar" a prioridade de um vértice, inserimos um novo par e descartamos pares velhos quando eles saem.

INSERE(h, (0, s))      # dist[s] <- 0; pred[s] <- s
ENQUANTO TAM(h) > 0 FAÇA

    _, k <- MENOR(h)                    # pega o com menor dist
    SE k já foi visitado ENTÃO continua loop FIM

    PARA CADA VIZINHO j DE k FAÇA
        distK <- dist[k] + P[k, j]
        SE distK < dist[j] ENTÃO
            dist[j] <- distK
            pred[j] <- k
            INSERE(h, (distK, j))        # insere o par (dist, índice),
                                         # usando dist como valor
        FIM
    FIM
FIM

Por que o SE k já foi visitado? Um mesmo vértice pode entrar várias vezes no heap (cada vez que achamos um caminho melhor). O par com a menor distância sai primeiro; os pares antigos (maiores) que saírem depois são obsoletos e devem ser ignorados.

Simulação com heap (fonte D)

Note o par obsoleto descartado: A entrou com 7, depois com 6 e depois com 5; só o par (5, A) conta.

Complexidade com heap

  • INSERE: O(log N); MENOR: O(log N).
  • O laço externo roda no máximo E vezes — por quê? Cada passada remove um par do heap e só inserimos um par a cada relaxamento bem-sucedido, que ocorre no máximo uma vez por aresta (+1 par inicial) ⇒ há no máximo ≈ E pares para remover.
  • O heap tem no máximo E pares e log E ≤ log V² = 2 log V ⇒ cada operação é O(log V).
  • Total: O(E log V).
VersãoCustoMelhor quando…
vetor para achar o menorO(V²)grafo denso (E ≈ V²): V² < V² log V
min-heapO(E log V)grafo esparso (E ≈ V): V log V ≪ V²

complemento Com matriz de adjacências, descobrir os vizinhos de k custa O(V) por vértice, então na prática há um termo O(V²) a mais; a análise dos slides conta só os relaxamentos (E) e as operações do heap.

Receitas para a prova

Ler/escrever a matriz

Linha = origem, coluna = destino. Aresta v→w ⇒ A[v][w]. Sem pesos: 1/0; com pesos: peso/∞. Não direcionado ⇒ simétrica. Grau de saída = soma da linha; grau de entrada = soma da coluna.

Simular DFS

Marque o vértice ao entrar; percorra vizinhos em ordem alfabética; só desça em vizinho não visitado; ao esgotar os vizinhos, volte. Visitado ≠ predecessor ⇒ ciclo. Vértices não numerados ⇒ outros componentes.

Simular BFS

Tabela com colunas desenfileira / novos / fila. Marque dist e pred ao enfileirar. Pare ao alcançar o destino. Caminho = seguir pred de t até s.

Simular Dijkstra

Tabela dist/pred/h. Em cada passo: escolha em h o de menor dist (esse fica definitivo), relaxe seus vizinhos, atualize só se menor (empate não atualiza). Pare ao processar o destino.

Simular heap

INSERE: põe no fim e sobe trocando com o pai enquanto for menor. MENOR: devolve a raiz, move o último para a raiz e desce trocando com o menor filho. Escreva sempre o array depois.

Modelar um problema

Responda as 4 perguntas: vértice? aresta? direção? peso? Depois traduza a pergunta do enunciado: "isolado?" → componentes; "menor nº de passos" → BFS; "menor custo/tempo/distância" → Dijkstra.

Pegadinhas clássicas

  1. BFS ≠ Dijkstra: BFS minimiza o nº de arestas; só é correta para o menor custo quando todas as arestas são equivalentes.
  2. DFS não encontra o menor caminho — encontra algum caminho.
  3. Dijkstra exige pesos ≥ 0; com pesos negativos o resultado pode estar errado (e ciclo negativo ⇒ nem existe mínimo).
  4. Matriz com pesos usa ∞ (INFINITY) para "sem aresta", não 0; sem pesos usa 0.
  5. malloc não zera: inicialize a matriz. E libere em dois níveis (linhas, depois o array de ponteiros).
  6. Componentes: mínimo 1, máximo |V|; os rótulos podem sair numerados em ordem diferente e ainda estar corretos.
  7. Índices do heap (0-based): filhos 2i+1 e 2i+2, pai (i−1)//2. O heap não é um vetor ordenado — só garante pai ≤ filhos.
  8. Dijkstra com heap: pares obsoletos saem do heap depois; por isso o teste "já visitado".
  9. Grafo não direcionado ⇒ matriz simétrica e grau único; cuidado ao contar arestas (cada linha desenhada vale 2 pares em E).
  10. Complexidades: Dijkstra O(V²) (vetor) × O(E log V) (heap); INSERE/MENOR O(log N).
